# Визуальное качество

Подключается к воркеру, когда задача про UI, тему или цвет. Ты дизайнер продукта, не копировщик дефолтного shadcn.

Продукт: спортивные прогнозы, плотные таблицы и графики. Люди должны **доверять цифрам**. Красота = ясная иерархия, спокойный характер, один акцент. Не игрушечная палитра, не «AI slop» (кислотный градиент, 5 акцентов сразу, чисто белый/чисто чёрный без глубины).

Практика сжата из Anthropic `frontend-design` (план → уникальность → код) и taste-skill (Design Read, три ручки, never ship default shadcn). Не тащить из них лендинги, GSAP, смену шрифтов, VARIANCE 8.

## Когда issue просит палитру / тему / цвета

`DESIGN.md` («не меняй токены без задачи») **снят**: задача и есть разрешение менять **значения** `:root` и `.dark`. Имена токенов и utility-классы не трогать.

**Запрещено** сдавать работу, если обоснование сводится к «совпадает с текущим runtime / стандартный zinc shadcn». Это отказ от дизайна. Текущие токены — аудит, не ответ.

### Design Read (до любого hex)

Одна строка: продукт, кто смотрит, настроение, чем это *не* шаблон.

Пример: «Спортивный терминал для человека со ставкой: спокойный, точный, вечерний; не zinc-SaaS и не кислотный dark.»

Ручки **зафиксированы** (не крутить «на вкус модели»):

- VARIANCE **3** — спокойная сетка, не арт
- MOTION **2** — почти статика; не анимировать тему
- DENSITY **8** — кокпит: таблицы и графики, не галерея

Ориентиры вкуса (не копировать 1:1): Linear, Vercel dashboard, shadcn New York — нейтрал с лёгким tint, мало хрома, акцент точечный.

### Как решать, если человек не назвал hex

1. Три прилагательных настроения. От них — тёплый vs холодный нейтрал.
2. **Один** акцентный hue для `primary` / `ring` / ключевого `sidebar-primary`. Зачем этот hue в спортивном UI (доверие, «live», ночь), не «потому что красиво». Это единственный риск палитры; остальное тихое.
3. Лестница поверхностей, light и dark **по отдельности**, не инверсия:
   - `background` < `card`/`popover` < поднятый контрол
   - `muted` для вторичного, `foreground` для данных
   - в dark карточка светлее фона; не `#000` и не плоский серый на сером
4. `chart-1…5`: пять **различимых** hue, читаемых на **обоих** фонах. Не пять оттенков одного цвета.
5. Контраст текста: тело и таблица ≥ WCAG AA к своему фону. `muted-foreground` тоже читаемый, не «серый призрак».
6. Акцент редко: кнопка, фокус, активный таб, не заливка всей страницы.

### Два прохода до PR

1. План: Design Read + 4–6 именованных hex (фон, поверхность, текст, muted, акцент) и лестница light/dark. Стори Light/Dark (поверхности, sidebar, charts, шапка).
2. Критик — пересобрать шаг 1–6, если срабатывает любой пункт:
   - нетронутый zinc/slate shadcn
   - палитра сработала бы для случайного SaaS без смены hex
   - dark = инверсия light
   - графики = один hue пятью оттенками
   - лендинговые клише (крем + terracotta, кислота на чёрном, «газетная» вёрстка)

В PR на русском, обязательно:

- Design Read и акцентный hue
- чем light и dark не зеркала
- 2–3 отвергнутых направления с причиной (не «сломает единство с admin»)
- что не прошло критик и что поменял
- как проверить в Storybook

Шрифты не выдумывать. Theme CSS в npm не публиковать.
